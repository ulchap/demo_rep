# Метрики работы агента — granitovo.by

## Принцип

Метрики отражают наблюдаемую работу над проектом, а не впечатление от ответа. Каждая цифра должна иметь источник: diff/файл, запуск проверки, журнал сессии или явное решение заказчика. Если данных нет — записывать «не измерялось», а не оценку на глаз.

## Фиксировать по завершении сессии

| Метрика | Как считать |
|---|---|
| Сессии и дата | Одна запись журнала на завершённую рабочую сессию; дату брать из фактической среды проекта. |
| Объём изменений | Число добавленных/изменённых файлов и краткое описание; исключать не относящиеся к проекту изменения. |
| Проверки | Команда/инструмент, охват и итог (прошла / не прошла / не запускалась). Не считать просмотр кода тестированием. |
| Требования | Число конкретных требований, закрытых проверенным результатом; отдельно — перенесённых/открытых. Не оценивать процент без списка требований и правил подсчёта. |
| Решения заказчика | Утверждено / отклонено / ожидает ответа; не считать предложенную концепцию утверждённой. |
| Блокеры и риски | Новые/закрытые блокеры с влиянием и ответственным следующим шагом. |
| Время агента | Только реально замеренное время активной работы по согласованному правилу. Пока нет автоматического таймера — не публиковать оценку длительности. |
| Качество ответа | Если понадобится, собирать оценку заказчика по одинаковой короткой шкале; не синтезировать самооценку агента. |

## Не использовать как факты без отдельного источника

- число токенов, задержка модели, точность, процент «автономности»;
- предполагаемая экономия денег или часов;
- рост позиций, трафика, конверсии или выручки до подключения аналитики и наличия данных;
- Lighthouse/SEO-баллы, если не записаны адрес страницы, дата, режим, инструмент и результат;
- универсальный «процент готовности сайта» без согласованной декомпозиции требований и знаменателя.
